## 1️⃣ 스캔 매칭 모드

**맵 없이 실시간 위치 인식 - Hector SLAM과 유사**

### 사용 방법

```bash
# Terminal 1: Gazebo 시뮬레이션 실행
ros2 launch asw_robot_gazebo_sim gazebo_rviz_display.launch.py

# Terminal 2: 라이다 실행
ros2 launch sc_mini_ros2 start.launch.py

# Terminal 3: SLAM 스캔 매칭 모드 실행
ros2 launch slam_toolbox_config slam_launch.py slam_mode:=scan_matching use_sim_time:=true

# Terminal 4: 로봇 제어
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args --remap cmd_vel:=cmd_vel_gazebo
```

### 주요 특징

- ✅ **사전 맵 불필요**: 맵이 없어도 바로 사용 가능
- ✅ **실시간 처리**: 20Hz 업데이트 주기로 빠른 반응
- ✅ **동시 매핑**: 위치 추정과 동시에 맵 생성
- ✅ **루프 클로저**: 정확도 향상을 위한 루프 감지
- ✅ **탐색 최적화**: 미지의 환경 탐색에 최적

### 맵 리셋 (필요시)

```bash
# 현재 맵을 지우고 새로 시작
ros2 service call /reset_map std_srvs/srv/Empty
```

### 언제 사용하나요?

- 처음 방문하는 환경에서 탐색할 때
- 빠른 테스트나 데모가 필요할 때
- 장애물 회피와 함께 사용할 때
- 맵을 저장할 필요가 없을 때

## 2️⃣ 매핑 모드

**환경 맵을 생성하고 저장**

### 사용 방법

```bash
# Terminal 1: Gazebo 시뮬레이션 실행
ros2 launch asw_robot_gazebo_sim gazebo_rviz_display.launch.py

# Terminal 2: 라이다 실행
ros2 launch sc_mini_ros2 start.launch.py

# Terminal 3: SLAM 매핑 모드 실행
ros2 launch slam_toolbox_config slam_launch.py slam_mode:=mapping use_sim_time:=true

# Terminal 4: 로봇을 제어하면서 맵 생성
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args --remap cmd_vel:=cmd_vel_gazebo
```

### 맵 저장하기

#### 방법 1: 이미지 파일로 저장 (PNG + YAML)

```bash
ros2 service call /slam_toolbox/save_map slam_toolbox/srv/SaveMap "name:
  data: 'my_map'"
```

이 명령어는 다음 두 파일을 생성합니다:
- `my_map.png`: 맵 이미지
- `my_map.yaml`: 맵 메타데이터

#### 방법 2: SLAM Toolbox 네이티브 포맷으로 저장

```bash
ros2 service call /slam_toolbox/serialize_map slam_toolbox/srv/SerializePoseGraph "filename:
  data: 'my_map.posegraph'"
```

이 방법은 SLAM의 모든 정보(포즈 그래프 등)를 포함하여 더 정확합니다.

### 저장 위치

모든 맵은 다음 디렉토리에 저장됩니다:
```
src/slam/slam_toolbox_config/maps/
```

### 맵 생성 팁

1. **천천히 이동**: 로봇을 천천히 움직여서 정확한 스캔 수집
2. **중복 방문**: 같은 장소를 여러 번 지나가면 루프 클로저로 정확도 향상
3. **전체 커버리지**: 환경의 모든 영역을 방문
4. **장애물 주의**: 벽과 장애물이 선명하게 보이는 경로 선택

### 언제 사용하나요?

- 환경의 영구적인 맵을 만들 때
- 나중에 반복적으로 방문할 장소를 매핑할 때
- 정확한 내비게이션이 필요할 때

## 3️⃣ 로컬라이제이션 모드

**저장된 맵으로 정확한 위치 추정**

### 사용 방법

```bash
# Terminal 1: Gazebo 시뮬레이션 실행
ros2 launch asw_robot_gazebo_sim gazebo_rviz_display.launch.py

# Terminal 2: 라이다 실행
ros2 launch sc_mini_ros2 start.launch.py

# Terminal 3: SLAM 로컬라이제이션 모드 실행 (맵 파일 경로 지정)
ros2 launch slam_toolbox_config slam_launch.py \
  slam_mode:=localization \
  use_sim_time:=true \
  map:=/home/amap/aMAP_ROS2_AA10_Simulator/src/slam/slam_toolbox_config/maps/my_map.yaml
```

### 주요 특징

- ⭐ **최고 정확도**: 사전 맵을 사용하여 가장 정확한 위치 추정
- ⭐ **빠른 처리**: 맵 생성 없이 위치 추정만 수행
- ⭐ **안정적**: 드리프트 최소화
- ⭐ **내비게이션**: Nav2와 함께 사용하여 자율 주행 가능

### 필수 조건

1. 매핑 모드로 생성한 맵 파일 (`.yaml` + `.png`)
2. 로봇이 맵과 비슷한 위치에서 시작

### 언제 사용하나요?

- 이미 맵을 만든 환경에서 작업할 때
- 정밀한 위치 추정이 필요할 때
- 자율 내비게이션을 할 때
- 반복적인 작업을 수행할 때

## 4️⃣ SLAM 제어 - 토픽과 서비스

SLAM Toolbox는 **토픽과 서비스** 두 가지 방법으로 제어할 수 있습니다.

### 📡 토픽으로 제어 (권장)

토픽을 사용하면 SLAM을 시작, 정지, 리셋할 수 있습니다.

#### SLAM Manager 실행

```bash
# SLAM Manager 노드 실행 (토픽 기반 제어 활성화)
ros2 run slam_toolbox_config slam_manager
```

#### 사용 가능한 명령어

```bash
# SLAM 시작
ros2 topic pub /slam_command std_msgs/msg/String "data: 'start'" --once

# SLAM 정지
ros2 topic pub /slam_command std_msgs/msg/String "data: 'stop'" --once

# SLAM 리셋 (정지 후 재시작)
ros2 topic pub /slam_command std_msgs/msg/String "data: 'reset'" --once

# SLAM 상태 확인
ros2 topic pub /slam_command std_msgs/msg/String "data: 'status'" --once
```

#### 상태 모니터링

```bash
# SLAM 상태 메시지 구독
ros2 topic echo /slam_status

# SLAM 실행 여부 확인 (Bool)
ros2 topic echo /slam_running
```

**출력 예시:**
```
🟢 RUNNING (PID: 12345)
또는
🔴 STOPPED
```

---

### 🔧 서비스로 제어

서비스를 사용하면 더 신뢰성 있는 제어가 가능합니다.

#### SLAM 시작/정지/리셋 서비스

```bash
# SLAM 시작
ros2 service call /slam_start std_srvs/srv/Empty

# SLAM 정지
ros2 service call /slam_stop std_srvs/srv/Empty

# SLAM 리셋 (정지 후 재시작)
ros2 service call /slam_reset std_srvs/srv/Empty
```

---

### 🔄 맵 리셋 (Hector SLAM 스타일)

현재 맵만 초기화하고 SLAM을 계속 실행하려면:

#### 방법 1: 간편한 서비스 사용

```bash
# Terminal 1: 맵 리셋 서비스 실행
ros2 run slam_toolbox_config map_reset_service

# Terminal 2: 맵 리셋 호출
ros2 service call /reset_map std_srvs/srv/Empty
```

#### 방법 2: 셸 스크립트 사용

```bash
bash src/slam/slam_toolbox_config/scripts/reset_map.sh
```

#### 방법 3: SLAM Toolbox 서비스 직접 호출

```bash
ros2 service call /slam_toolbox/clear_changes slam_toolbox/srv/Clear
```

---

### 📊 토픽 vs 서비스 비교

| 방법 | 장점 | 단점 | 추천 용도 |
|------|------|------|----------|
| **토픽** | 간단, 빠름, GUI 연동 쉬움 | 응답 확인 불가 | 자동화, GUI, 스크립트 |
| **서비스** | 응답 확인, 신뢰성 높음 | 약간 복잡 | 정밀 제어, 에러 처리 |

---

### 💡 실전 예제: GUI나 스크립트에서 SLAM 제어

#### Python 예제

```python
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from std_msgs.msg import String

class SlamController(Node):
    def __init__(self):
        super().__init__('slam_controller')
        self.pub = self.create_publisher(String, '/slam_command', 10)

    def start_slam(self):
        msg = String()
        msg.data = 'start'
        self.pub.publish(msg)
        self.get_logger().info('SLAM 시작 명령 전송')

    def stop_slam(self):
        msg = String()
        msg.data = 'stop'
        self.pub.publish(msg)
        self.get_logger().info('SLAM 정지 명령 전송')

    def reset_slam(self):
        msg = String()
        msg.data = 'reset'
        self.pub.publish(msg)
        self.get_logger().info('SLAM 리셋 명령 전송')

# 사용 예
rclpy.init()
controller = SlamController()
controller.start_slam()  # SLAM 시작
# ... 작업 수행 ...
controller.reset_slam()  # SLAM 리셋
rclpy.shutdown()
```

#### Bash 스크립트 예제

```bash
#!/bin/bash

# SLAM 시작
echo "SLAM 시작..."
ros2 topic pub /slam_command std_msgs/msg/String "data: 'start'" --once
sleep 5

# 로봇 작업 수행
echo "작업 수행 중..."
# ... 로봇 제어 명령 ...

# 맵 리셋
echo "맵 리셋..."
ros2 service call /reset_map std_srvs/srv/Empty

# SLAM 정지
echo "SLAM 정지..."
ros2 topic pub /slam_command std_msgs/msg/String "data: 'stop'" --once
```

### 🎮 통합 제어 시스템

모든 제어 방법을 한눈에:

```bash
# === 토픽 제어 ===
ros2 topic pub /slam_command std_msgs/msg/String "data: 'start|stop|reset|status'" --once

# === 서비스 제어 ===
ros2 service call /slam_start std_srvs/srv/Empty     # SLAM 시작
ros2 service call /slam_stop std_srvs/srv/Empty      # SLAM 정지
ros2 service call /slam_reset std_srvs/srv/Empty     # SLAM 리셋

# === 맵만 리셋 ===
ros2 service call /reset_map std_srvs/srv/Empty      # 맵 초기화 (SLAM 계속 실행)
ros2 service call /slam_toolbox/clear_changes slam_toolbox/srv/Clear  # 직접 호출

# === 상태 모니터링 ===
ros2 topic echo /slam_status     # 상태 메시지
ros2 topic echo /slam_running    # 실행 여부 (Bool)
```

## 5️⃣ 실제 로봇에서 사용

시뮬레이션이 아닌 실제 AA10 로봇에서 사용할 때는 `use_sim_time:=false`로 설정합니다.

### 스캔 매칭 모드

```bash
ros2 launch slam_toolbox_config slam_launch.py slam_mode:=scan_matching use_sim_time:=false
```

### 매핑 모드

```bash
ros2 launch slam_toolbox_config slam_launch.py slam_mode:=mapping use_sim_time:=false
```

### 로컬라이제이션 모드

```bash
ros2 launch slam_toolbox_config slam_launch.py \
  slam_mode:=localization \
  use_sim_time:=false \
  map:=/path/to/your/map.yaml
```

### 실제 로봇 사용 시 주의사항

1. **라이다 연결 확인**: `ros2 topic echo /scan --once`
2. **TF 프레임 확인**: `base_footprint` 프레임이 존재하는지 확인
3. **센서 캘리브레이션**: 라이다 위치와 각도가 정확한지 확인
4. **바닥 상태**: 평평한 바닥에서 사용 권장

## 📊 모드 비교

| 모드 | 사전 맵 필요 | 정확도 | 처리 속도 | 주요 용도 | 맵 저장 |
|------|-------------|--------|-----------|----------|---------|
| **scan_matching** | ❌ 불필요 | ⭐⭐⭐ | ⭐⭐⭐⭐ | 실시간 탐색, 빠른 테스트 | 가능 |
| **mapping** | ❌ 불필요 | ⭐⭐⭐⭐ | ⭐⭐⭐ | 맵 생성, 환경 학습 | 필수 |
| **localization** | ✅ 필요 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | 정밀 위치 추정, 자율 주행 | 불가 |

### 선택 가이드

```
미지의 환경 탐색?
  └─ YES → scan_matching 모드
  └─ NO → 맵이 있나요?
      └─ NO → mapping 모드로 맵 생성
      └─ YES → localization 모드
```

## 💡 추천 사용 순서

### 초보자용 워크플로우

```
1단계: 스캔 매칭으로 시작
  └─ ros2 launch slam_toolbox_config slam_launch.py slam_mode:=scan_matching
  └─ 목적: 시스템 동작 확인 및 기본 테스트

2단계: 매핑 모드로 맵 생성
  └─ ros2 launch slam_toolbox_config slam_launch.py slam_mode:=mapping
  └─ 로봇을 천천히 움직이며 전체 환경 스캔
  └─ ros2 service call /slam_toolbox/save_map ... (맵 저장)

3단계: 로컬라이제이션으로 정밀 작업
  └─ ros2 launch slam_toolbox_config slam_launch.py slam_mode:=localization map:=...
  └─ 저장한 맵으로 정확한 위치 추정
```

### 고급 사용자용 워크플로우

```
개발/테스트 단계:
  └─ scan_matching: 빠른 반복 테스트

배포 준비:
  └─ mapping: 각 환경별 맵 생성 및 저장

실제 운영:
  └─ localization: 저장된 맵으로 안정적 운영
```

## 🔧 문제 해결 (Troubleshooting)

### 1. 맵이 업데이트되지 않음

**증상**: RViz에 맵이 나타나지 않거나 업데이트되지 않음

**해결 방법**:
```bash
# 라이다 데이터 확인
ros2 topic echo /scan --once

# 라이다가 퍼블리시하는지 확인
ros2 topic hz /scan

# 라이다 런치 파일 실행 확인
ros2 launch sc_mini_ros2 start.launch.py
```

### 2. TF 변환 오류

**증상**: `Could not transform ... to map` 같은 에러 메시지

**해결 방법**:
```bash
# TF 트리 확인
ros2 run tf2_tools view_frames

# base_footprint 프레임 존재 확인
ros2 topic echo /tf --once | grep base_footprint
```

### 3. 로봇 위치가 튀거나 부정확함

**증상**: 로봇이 순간이동하거나 위치가 불안정함

**해결 방법**:
- `config/` 폴더의 파라미터 파일에서 `minimum_travel_distance` 조정
- 라이다 주변의 장애물이 충분한지 확인
- 로봇을 천천히 움직이기

### 4. 로컬라이제이션 모드에서 맵을 찾을 수 없음

**증상**: `Could not load map` 오류

**해결 방법**:
```bash
# 맵 파일 경로 확인 (절대 경로 사용)
ls -l /home/amap/aMAP_ROS2_AA10_Simulator/src/slam/slam_toolbox_config/maps/
```

## 🎯 실전 예제

### 예제 1: 미로 탐색하기

```bash
# 1. 시뮬레이션 실행
ros2 launch asw_robot_gazebo_sim gazebo_rviz_display.launch.py

# 2. 라이다 실행
ros2 launch sc_mini_ros2 start.launch.py

# 3. 스캔 매칭으로 탐색 시작
ros2 launch slam_toolbox_config slam_launch.py slam_mode:=scan_matching use_sim_time:=true

# 4. 벽 추종 알고리즘과 함께 사용
ros2 launch wall_maze wall_maze.launch.py

# RViz에서 실시간으로 맵이 생성되는 것을 확인하세요!
```

### 예제 2: 환경 매핑 후 반복 운행

```bash
# Phase 1: 맵 생성
ros2 launch slam_toolbox_config slam_launch.py slam_mode:=mapping use_sim_time:=true

# 로봇을 움직여서 맵 생성
# ...

# 맵 저장
ros2 service call /slam_toolbox/save_map slam_toolbox/srv/SaveMap "name:
  data: 'stadium_map'"

# Phase 2: 저장된 맵으로 운행
ros2 launch slam_toolbox_config slam_launch.py \
  slam_mode:=localization \
  use_sim_time:=true \
  map:=/home/amap/aMAP_ROS2_AA10_Simulator/src/slam/slam_toolbox_config/maps/stadium_map.yaml
```

### 예제 3: 실시간 위치 모니터링

```bash
# Terminal 1: SLAM 실행
ros2 launch slam_toolbox_config slam_launch.py slam_mode:=scan_matching use_sim_time:=true

# Terminal 2: 위치 실시간 출력
watch -n 0.1 'ros2 run tf2_ros tf2_echo map base_footprint'

# Terminal 3: 로봇 제어
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args --remap cmd_vel:=cmd_vel_gazebo
```
